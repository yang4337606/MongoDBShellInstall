快速开始

MongoDBShellInstall 是一款 MongoDB 一键自动化安装脚本，支持 MongoDB 5.x 至 8.x 全版本，同时支持单机和副本集两种部署模式。脚本自动完成操作系统参数优化、MongoDB 解压安装（三包：server / mongosh / database-tools）、版本感知配置生成、WiredTiger 调优、systemd 服务创建及副本集远程部署全流程。

三步安装

  1. 上传软件包 - 将 MongoDB.sh 脚本和 MongoDB 离线安装包上传至服务器 /soft 目录
  2. 配置参数 - 使用 命令生成器 或手动拼接安装参数
  3. 执行安装 - 在 /soft 目录下以 root 用户执行
Shell
bash MongoDB.sh -m single
注意：脚本必须以 root 用户执行。Bash 版本需 >= 4。支持 RHEL/CentOS/Rocky/Alma/Debian/Ubuntu/SLES/Arch 等主流 Linux 发行版。

环境准备

目录结构

将以下文件放置在 /soft 目录下：

目录结构
/soft/ MongoDB.sh # 安装脚本 mongodb-linux-x86_64-rhel80-8.0.9.tgz # MongoDB Server 安装包 mongosh-2.3.8-linux-x64.tgz # mongosh 安装包 mongodb-database-tools-rhel80-x86_64-100.*.tgz # database-tools 安装包 mongdb-offline-rpm.tar.gz # ISO 缺失的 OS 依赖补充包（可选）

系统要求

  • 支持的操作系统：RHEL/CentOS 7/8/9、Rocky/Alma 8/9、Ubuntu 18-24、Debian 10-13、SLES/openSUSE、Amazon Linux、Fedora、Arch Linux
  • Bash 版本 >= 4，脚本最低检查 1GB 内存（生产环境建议至少 8GB）
  • 磁盘空间：MongoDB 安装约 500MB，数据目录建议使用 XFS 文件系统
  • 副本集模式：所有节点使用可解析的 DNS 主机名，网络互通，SSH 主机密钥已写入 known_hosts，仅在第一个节点执行脚本

离线安装包

MongoDB Server 包是必需项；MongoDB 6.0+ 还必须提供独立 mongosh 包。Database Tools 可选，但缺少时不会启用自动数据库备份：

  • mongodb-linux-x86_64-*.tgz - MongoDB Server（包含 mongod）
  • mongosh-*-linux-x64.tgz - MongoDB Shell（MongoDB 6.0+ 必需；旧版可使用 Server 包内的 legacy mongo）
  • mongodb-database-tools-*.tgz - 数据库工具（可选；自动备份需要 mongodump 100.3.0+）
  • mongdb-offline-rpm.tar.gz - ISO 中缺失的 OS RPM 及完整依赖闭包（可选）

OS 离线包必须按 OS ID + OS 主版本 + CPU 架构 隔离。示例结构：

归档内部目录
mongdb-offline-rpm/ rhel/ 8/x86_64/ 9/ x86_64/ *.rpm rocky/ 8/x86_64/ 9/x86_64/ centos/ 7/x86_64/

mongdb-offline-rpm.tar.gz 仅在指定 ISO 确实缺少依赖时提供；归档内部只允许包含 RPM 依赖包，不放清单、校验文件或其他辅助文件，也不增加 SHA256SUMS 校验。当前测试使用的 RHEL 8/9、Rocky Linux 8/9 与 CentOS 7 完整 DVD ISO 已包含安装所需系统依赖，因此无需补充包。密码首次登录改用 OpenSSH 原生 SSH_ASKPASS 建立 Ed25519 公钥信任，不再依赖 sshpass。tools/build_offline_rpm_bundle.sh 仅供维护者在更换 ISO 或增加 OS/架构并确认实际缺包后重建介质。安装时先尝试 --os-iso-root 指定的已挂载 ISO，再使用确有需要的补充包，最后才尝试在线仓库。

提示：只有一个 MongoDB Server 包时自动选择；有多个时交互选择。非交互安装存在多个包时必须通过 --mongo-package 指定文件名或版本。脚本会校验 Server 包和 OS 离线包，Server 包文件名不得包含 "database-tools" 或 "mongosh"。

安装介质

脚本可识别 MongoDB 5.x 至 8.x 的离线包并生成版本感知配置。生产部署应选用 MongoDB 官方仍在支持期内、且与当前操作系统匹配的版本与构建。

MongoDB 版本安装包文件名示例版本特性

7.0mongodb-linux-x86_64-rhel80-7.0.20.tgz需禁用 THP

工作原理

MongoDBShellInstall 脚本按照以下流程自动完成整个安装过程：

执行流程

  1. 参数校验 - 验证数值范围、安全目录、绑定地址、凭据文件和副本集 DNS 主机名
  2. 安装确认 - 显示安装摘要，等待用户确认
  3. 版本检测 - 解析 MongoDB 安装包版本号，确定版本特性
  4. OS 优化 - 内核参数、limits、THP、NUMA、readahead，并停止/禁用防火墙、关闭 SELinux
  5. 用户创建 - 创建 mongod 系统用户，配置目录权限
  6. MongoDB 安装 - 解压三个离线包，创建二进制符号链接
  7. 配置生成 - 生成版本感知的 mongod.conf（WiredTiger 调优）
  8. Systemd 服务 - 创建服务文件，NUMA interleave 启动
  9. 启动服务 - 启动 MongoDB 并验证 ping 响应
  10. 远程部署 - （副本集模式）scp 同步到从节点，调整配置并启动
  11. 副本集初始化 - rs.initiate、等待 PRIMARY 选举、创建管理员用户

单机安装

单机模式是最简单的部署方式，适用于开发测试及中小型数据存储场景。

最简安装

Shell
bash MongoDB.sh -m single

自定义安装

Shell
bash MongoDB.sh \ -m single \ -d /data/mongodb \ -p 27018 \ --max-connections 20000 \ --backup-days 14

启用认证的非交互安装

Shell
bash MongoDB.sh \ -m single \ --auth \ --admin-user admin \ --admin-pass-file /root/.mongodb-admin-password \ --yes

应用服务器远程连接

默认监听 0.0.0.0，远程应用可直接使用 MongoDB 服务器的可达 IP 连接。默认未启用认证时，连接串无需账号密码：

URI
mongodb://10.20.0.10:27017/appdb

启用认证后，使用 mongodb://admin:<URL编码密码>@10.20.0.10:27017/admin?authSource=admin&authMechanism=SCRAM-SHA-256。安装摘要会在终端显示管理员账号、密码与认证方式，但密码不会写入脚本生成的详细日志。

如需只允许本机连接，可显式指定 --bind-ip 127.0.0.1，再通过 SSH 隧道访问：ssh -N -L 27018:127.0.0.1:27017 ops@10.20.0.10。

高风险默认值：脚本默认未认证、未启用 TLS、监听 0.0.0.0，并关闭防火墙与 SELinux。任何网络可达主机都可能读写或删除数据。请仅在隔离网络使用；生产环境应至少启用 --auth，并通过云安全组、上游防火墙或专用网络限制来源。需要传输加密时显式使用 --tls。
说明：单机模式下数据存储在 /mongodb/data 目录，日志存储在 /mongodb/logs 目录。WiredTiger 缓存按有效内存自动计算，容器环境会采用 cgroup 内存上限。

副本集安装

副本集模式是 MongoDB 生产环境推荐的部署方式，提供数据冗余和自动故障转移能力。

前置条件：所有节点必须能相互解析 DNS 主机名，网络互通，SSH 主机密钥须预先核验并写入 known_hosts。推荐 SSH 密钥登录；节点数建议奇数（3/5/7）。

基础 3 节点副本集

Shell
bash MongoDB.sh \ -m replicaset \ --hosts db1.example.internal,db2.example.internal,db3.example.internal \ --remote-ips 10.0.1.11,10.0.1.12,10.0.1.13 \ --ssh-key /root/.ssh/id_ed25519 \ --auth \ --admin-pass-file /root/.mongodb-admin-password

自定义副本集配置

Shell
bash MongoDB.sh \ -m rs \ --hosts db1.example.internal,db2.example.internal,db3.example.internal \ --remote-ips 10.0.1.11,10.0.1.12,10.0.1.13 \ --root-pass-file /root/.mongodb-ssh-password \ -ss 22022 \ -d /data/mongodb \ -p 27017 \ --repl-set myRS \ --oplog-size 4096 \ --auth \ --admin-pass-file /root/.mongodb-admin-password

副本集安装流程

  1. 主节点完成 OS 优化 + MongoDB 三包安装 + 配置生成
  2. 启用 --auth 时默认生成 keyFile；也可配合 TLS 选择 X.509 节点内部认证
  3. 启动主节点 MongoDB
  4. 并行配置远程节点；远端版本与二进制指纹均一致时跳过重复传输，否则复用主节点的一份压缩包更新
  5. 从节点调整配置（bindIp）并启动
  6. 执行 rs.initiate 初始化副本集
  7. 等待 PRIMARY 选举完成
  8. 启用认证时通过 localhost exception 创建 SCRAM-SHA-256 管理员，并立即验证凭据
生产认证建议：keyFile 仍是默认的节点内部认证方式；通过 --tls --cluster-auth-mode x509 可选择 X.509。证书和 CA 必须由外部 PKI 预先签发，脚本只做有效期、SAN、用途、私钥匹配、成员 O/OU/DC 一致性校验以及安装分发，不签发证书。参见 官方 X.509 成员认证文档。

TLS + X.509 副本集

证书目录中必须按副本集成员主机名保存 PEM，例如 /root/pki/members/db1.example.internal.pem。每个 PEM 同时包含成员证书和未加密私钥，权限为 600；SAN 必须包含对应主机名和脚本本机引导使用的 127.0.0.1。

Shell
bash MongoDB.sh \ -m replicaset \ --hosts db1.example.internal,db2.example.internal,db3.example.internal \ --remote-ips 10.0.1.11,10.0.1.12,10.0.1.13 \ --ssh-key /root/.ssh/id_ed25519 \ --auth \ --admin-pass-file /root/.mongodb-admin-password \ --tls \ --tls-ca-file /root/pki/ca.pem \ --tls-cert-dir /root/pki/members \ --cluster-auth-mode x509

系统优化说明

脚本会自动完成以下操作系统级优化（遵循 MongoDB 官方生产部署建议）：

  • vm.swappiness=1 - 最小化 swap 使用
  • tcp_keepalive_time=120 - MongoDB 推荐值
  • vm.max_map_count - 仅在当前值不足 262144 时提高，不降低系统已有值
  • readahead=16KB - WiredTiger 推荐值（8-32 范围）
  • vm.zone_reclaim_mode=0 - 禁用 NUMA zone reclaim
  • NUMA interleave - numactl --interleave=all 启动 mongod
  • THP 版本感知 - MongoDB 8.0+ 启用 THP（TCMalloc），7.0- 禁用 THP
  • limits 资源联动 - 根据 maxIncomingConnections、CPU 数量和 fs.nr_open 计算 nofile/nproc，并按官方要求配置 fsize、cpu、as、memlock 为 unlimited
  • WiredTiger 内存联动 - 按官方默认公式基于物理内存计算缓存并为 OS 文件缓存保留空间，不盲目放大
  • Oplog 磁盘联动 - 副本集未显式指定时按数据盘可用空间计算，并设置合理上下限
  • 保守网络/内核调整 - 只提高不足的队列、文件和进程容量，不覆盖自适应 TCP 缓冲、TIME_WAIT 或脏页策略
  • XFS 文件系统 - 推荐使用 XFS 作为数据目录文件系统
  • 系统安全策略 - 停止并禁用 firewalld/ufw/iptables/nftables，当前会话将 SELinux 切换为 Permissive，并配置重启后完全关闭

参数依据：Production Notes、UNIX ulimit Settings、Operations Checklist。脚本只修改已登记且能判定适用范围的参数，不会因高版本移除某选项而从其他受支持版本全局删除。

故障排查

MongoDB 启动超时

  • 查看日志：journalctl -u mongod 或 /mongodb/logs/mongod.log
  • 检查 WiredTiger 缓存大小是否超出可用内存
  • 确认数据目录权限归 mongod 用户所有
  • 检查端口是否被占用：ss -tlnp | grep 27017

副本集初始化失败

  • 确认所有节点 MongoDB 已启动并可 ping 通
  • MongoDB 5.0+ 必须使用 DNS 主机名，并确保每个节点都能解析全部成员
  • 检查所有节点的 replSetName 配置一致
  • keyFile 模式验证权限为 400 且内容一致；X.509 模式验证各成员证书链、SAN、用途和 O/OU/DC 一致
  • 确认节点间端口互通：nc -zv peer_ip 27017

认证失败

  • 确认密码文件为普通文件、非符号链接，且权限为 600
  • 连接时使用：mongosh --host 127.0.0.1 --port 27017 -u admin --password --authenticationDatabase admin --authenticationMechanism SCRAM-SHA-256，随后交互输入密码
  • 副本集模式下 keyFile 权限应为 400，属主和属组都应为 --owner 指定用户，例如：chown mongoops:mongoops /mongodb/keyfile && chmod 400 /mongodb/keyfile

版本配置不兼容

  • MongoDB 6.1+ 不支持 storage.journal.enabled 选项，脚本已自动处理
  • MongoDB 8.0+ 需要启用 THP，脚本已自动检测版本并配置
  • MongoDB 5.0+ 的 enableMajorityReadConcern 始终为 true，无需配置

常见问题

Q: 支持哪些 MongoDB 版本？

脚本可识别 MongoDB 5.x 至 8.x 安装包。生产环境应使用 MongoDB 官方仍在支持期内、且适配当前操作系统的版本。

Q: 为什么需要三个安装包？

从 MongoDB 4.4 开始，MongoDB 官方将 Server、mongosh 和 database-tools 拆分为独立发布包。脚本自动识别并安装这三个包。

Q: 是否支持离线安装？

支持。将 MongoDB 的 Server、mongosh、database-tools 包放入 /soft；ISO 缺失的系统依赖使用 mongdb-offline-rpm.tar.gz。安装器仅加载与当前 OS ID/主版本/CPU 架构 完全匹配的目录，例如 mongdb-offline-rpm/rhel/9/x86_64/，防止跨平台混装。

Q: WiredTiger 缓存大小如何计算？

脚本按照 MongoDB 官方建议自动计算：max(0.25GB, (totalRAM - 1GB) * 0.5)。如物理内存 16GB 则缓存约 7.5GB。

Q: 为什么 MongoDB 8.0 要启用 THP？

MongoDB 8.0 将内存分配器切换为 Google TCMalloc（取代 jemalloc/glibc），TCMalloc 与 THP 配合可提升内存分配效率。7.0 及更早版本仍应禁用 THP。

Q: --owner 指定的用户可以登录吗？

不可以。脚本为该用户配置 /sbin/nologin 并锁定密码，将其同名组设为主组。MongoDB 通过 systemd 以同一用户和组（例如 User=mongoops、Group=mongoops）运行。
