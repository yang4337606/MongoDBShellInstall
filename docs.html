快速开始

MongoDBShellInstall 是一款 MongoDB 一键自动化安装脚本，支持 MongoDB 5.x 至 8.x 全版本，同时支持单机和副本集两种部署模式。脚本自动完成操作系统参数优化、MongoDB 解压安装（三包：server / mongosh / database-tools）、版本感知配置生成、WiredTiger 调优、systemd 服务创建及副本集远程部署全流程。

三步安装

  1. 上传软件包 - 将 MongoDB.sh 脚本和 MongoDB 离线安装包上传至服务器 /soft 目录
  2. 配置参数 - 使用 命令生成器 或手动拼接安装参数
  3. 执行安装 - 在 /soft 目录下以 root 用户执行
Shell
bash MongoDB.sh -m single # 单机模式，最简安装
注意：脚本必须以 root 用户执行。Bash 版本需 >= 4。支持 RHEL/CentOS/Rocky/Alma/Debian/Ubuntu/SLES/Arch 等主流 Linux 发行版。

环境准备

目录结构

将以下文件放置在 /soft 目录下：

目录结构
/soft/ MongoDB.sh # 安装脚本 mongodb-linux-x86_64-rhel80-8.0.9.tgz # MongoDB Server 安装包 mongosh-2.3.8-linux-x64.tgz # mongosh 安装包 mongodb-database-tools-rhel80-x86_64-100.*.tgz # database-tools 安装包

系统要求

  • 支持的操作系统：RHEL/CentOS 7/8/9、Rocky/Alma 8/9、Ubuntu 18-24、Debian 10-13、SLES/openSUSE、Amazon Linux、Fedora、Arch Linux
  • Bash 版本 >= 4，内存 >= 2GB（生产环境建议 >= 8GB）
  • 磁盘空间：MongoDB 安装约 500MB，数据目录建议使用 XFS 文件系统
  • 副本集模式：所有节点 root 密码一致，网络互通，仅在第一个节点执行脚本

离线安装包

MongoDB 离线安装需要三个独立的 tar.gz 包：

  • mongodb-linux-x86_64-*.tgz - MongoDB Server（包含 mongod）
  • mongosh-*-linux-x64.tgz - MongoDB Shell（交互式客户端）
  • mongodb-database-tools-*.tgz - 数据库工具（mongodump / mongorestore 等）
提示：脚本会自动识别这三个包并分别安装。请确保 Server 包的文件名不包含 "database-tools" 或 "mongosh" 关键字以避免误识别。

安装介质

脚本支持 MongoDB 5.x 至 8.x 全版本。将 .tgz 文件放置在 /soft 目录下，脚本启动后会自动识别版本并生成版本感知的配置文件。

工作原理

MongoDBShellInstall 脚本按照以下流程自动完成整个安装过程：

执行流程

  1. 参数校验 - 验证输入参数、节点 IP 格式和重复检测
  2. 安装确认 - 显示安装摘要，等待用户确认
  3. 版本检测 - 解析 MongoDB 安装包版本号，确定版本特性
  4. OS 优化 - 内核参数、limits、THP、NUMA、readahead、防火墙
  5. 用户创建 - 创建 mongod 系统用户，配置目录权限
  6. MongoDB 安装 - 解压三个离线包，创建二进制符号链接
  7. 配置生成 - 生成版本感知的 mongod.conf（WiredTiger 调优）
  8. Systemd 服务 - 创建服务文件，NUMA interleave 启动
  9. 启动服务 - 启动 MongoDB 并验证 ping 响应
  10. 远程部署 - （副本集模式）scp 同步到从节点，调整配置并启动
  11. 副本集初始化 - rs.initiate、等待 PRIMARY 选举、创建管理员用户

单机安装

单机模式是最简单的部署方式，适用于开发测试及中小型数据存储场景。

最简安装

Shell
bash MongoDB.sh -m single # 最简安装

自定义安装

Shell
bash MongoDB.sh \ -m single \ -d /data/mongodb \ # 安装根目录 -p 27018 \ # MongoDB 端口 --max-connections 20000 \ # 最大连接数 --backup-days 14 # 备份保留 14 天

带认证的单机安装

Shell
bash MongoDB.sh \ -m single \ --auth \ # 启用认证 --admin-user admin \ # 管理员用户名 --admin-pass 'SecurePass123' # 管理员密码
说明：单机模式下数据存储在 /mongodb/data 目录，日志存储在 /mongodb/logs 目录。WiredTiger 缓存大小根据物理内存自动计算。

副本集安装

副本集模式是 MongoDB 生产环境推荐的部署方式，提供数据冗余和自动故障转移能力。

前置条件：所有节点 root 密码必须一致，网络互通，脚本仅在第一个节点执行。节点数建议奇数（3/5/7）。

基础 3 节点副本集

Shell
bash MongoDB.sh \ -m replicaset \ -ri 192.168.1.11,192.168.1.12,192.168.1.13 \ -rp 'RootPass123' \ --auth \ --admin-pass 'MongoAdmin123'

自定义副本集配置

Shell
bash MongoDB.sh \ -m rs \ # rs 为 replicaset 简写 -ri 192.168.1.11,192.168.1.12,192.168.1.13 \ -rp 'RootPass123' \ -ss 22022 \ # SSH 端口 -d /data/mongodb \ # 安装根目录 -p 27017 \ # MongoDB 端口 --repl-set myRS \ # 副本集名称 --oplog-size 4096 \ # Oplog 大小 4GB --auth \ --admin-pass 'MongoAdmin123'

副本集安装流程

  1. 主节点完成 OS 优化 + MongoDB 三包安装 + 配置生成
  2. 生成 keyFile（副本集内部认证）
  3. 启动主节点 MongoDB
  4. scp 整个安装目录到从节点
  5. 从节点调整配置（bindIp）并启动
  6. 执行 rs.initiate 初始化副本集
  7. 等待 PRIMARY 选举完成
  8. 创建管理员用户（如启用 --auth）

系统优化说明

脚本会自动完成以下操作系统级优化（遵循 MongoDB 官方生产部署建议）：

  • vm.swappiness=1 - 最小化 swap 使用
  • tcp_keepalive_time=120 - MongoDB 推荐值
  • vm.max_map_count=262144 - 支持大量映射文件
  • readahead=16KB - WiredTiger 推荐值（8-32 范围）
  • vm.zone_reclaim_mode=0 - 禁用 NUMA zone reclaim
  • dirty_expire_centisecs=3000 - 优化脏页过期时间
  • NUMA interleave - numactl --interleave=all 启动 mongod
  • THP 版本感知 - MongoDB 8.0+ 启用 THP（TCMalloc），7.0- 禁用 THP
  • limits 配置 - nofile 65535, nproc 65535, memlock unlimited, core unlimited
  • XFS 文件系统 - 推荐使用 XFS 作为数据目录文件系统

故障排查

MongoDB 启动超时

  • 查看日志：journalctl -u mongod 或 /mongodb/logs/mongod.log
  • 检查 WiredTiger 缓存大小是否超出可用内存
  • 确认数据目录权限归 mongod 用户所有
  • 检查端口是否被占用：ss -tlnp | grep 27017

副本集初始化失败

  • 确认所有节点 MongoDB 已启动并可 ping 通
  • 检查所有节点的 replSetName 配置一致
  • 验证 keyFile 权限为 400 且内容一致
  • 确认节点间端口互通：nc -zv peer_ip 27017

认证失败

  • 确认使用 --auth 和 --admin-pass 参数
  • 连接时使用：mongosh --host IP --port 27017 -u admin -p 'password' --authenticationDatabase admin
  • 副本集模式下 keyFile 路径和权限：chmod 400 /mongodb/keyfile && chown mongod /mongodb/keyfile

版本配置不兼容

  • MongoDB 6.2+ 不支持 storage.journal.enabled 选项，脚本已自动处理
  • MongoDB 8.0+ 需要启用 THP，脚本已自动检测版本并配置
  • MongoDB 5.0+ 的 enableMajorityReadConcern 始终为 true，无需配置

常见问题

Q: 支持哪些 MongoDB 版本？

支持 MongoDB 5.x 至 8.x 全版本。脚本会根据版本自动调整配置参数（journal、THP、TCMalloc 等）。

Q: 为什么需要三个安装包？

从 MongoDB 4.4 开始，MongoDB 官方将 Server、mongosh 和 database-tools 拆分为独立发布包。脚本自动识别并安装这三个包。

Q: 是否支持离线安装？

支持。将三个 tar.gz 安装包上传至 /soft 目录即可，无需网络连接。系统依赖（numactl 等）需通过本地包源或提前安装。

Q: WiredTiger 缓存大小如何计算？

脚本按照 MongoDB 官方建议自动计算：max(0.25GB, (totalRAM - 1GB) * 0.5)。如物理内存 16GB 则缓存约 7.5GB。

Q: 为什么 MongoDB 8.0 要启用 THP？

MongoDB 8.0 将内存分配器切换为 Google TCMalloc（取代 jemalloc/glibc），TCMalloc 与 THP 配合可提升内存分配效率。7.0 及更早版本仍应禁用 THP。

Q: mongod 用户可以登录吗？

不可以。脚本创建的 mongod 用户 shell 为 /sbin/nologin，这是一个纯服务用户。MongoDB 通过 systemd（User=mongod）启动。
